# 对运行期可丢弃码流包采用 IDR 重同步

相机路输入会话成功打开并进入运行期后（包括首个 IDR 到达前），能够在进入 VDEC 前隔离的单个空包、非 Annex-B 包或浅层 NAL 结构无效包不再触发全局失败；程序丢弃该包及后续依赖画面，并在首个有效 IDR 确认成功送入 VDEC 后结束包级重同步。直接发送下一个 P/B 画面可能沿用已经断裂的参考链，而每个坏包都重建 RTSP/VDEC 又会放大瞬时故障，因此选择复用现有等待 IDR 机制，并以独立于初始 IDR 门控的最小周期状态记录错误驱动的重同步。每轮锁定一个不可由状态事件、再次读取或持续丢包刷新的绝对读取截止时间；截止前仍无有效 IDR 时，才按超时进入每路三次的既有有界恢复。初始输入规格、BSF、内存、内部状态和资源错误仍为全局致命故障。

## Consequences

- IDR 重同步期间，未处于会话恢复的相机路为 `resynchronizing`；仍在恢复且尚无健康解码帧时继续为 `reconnecting`。包级重同步不消耗恢复预算，健康结束允许保留历史无效包诊断并返回成功。
- 包级重同步若打断尚未完成的恢复稳定窗口，有效 IDR 成功送流后从该时刻重新累计完整稳定窗口；重同步期间不能重置既有预算。
- 路线快照以单调递增的重同步代次使性能监测能够识别并丢弃跨越短暂重同步的旧统计窗口。
- 不增加坏包次数或频率阈值；频繁但能及时完成重同步的坏包只告警，持续无有效 IDR 则由现有读取超时提供有界升级。
- 用户停止或运行时长到期时若仍在重同步，程序有序清理后返回失败。
